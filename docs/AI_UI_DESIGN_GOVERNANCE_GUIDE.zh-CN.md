# AI UI Design Governance 完整工程实施与治理指南

> **核心哲学：** 解决 AI 生成界面“AI 塑料味（AI Slop）”的根本途径，绝不是撰写一段华丽的 Prompt，而是把产品上下文、设计人格、设计规范、设计 Token、页面规格和真实浏览器视觉验收，转化为项目中长期可机器执行的工程资产。

---

## 一、 背景与痛点：什么是“AI 塑料味”？

在当前的 AI Coding 与 Vibe Coding 实践中，前端界面设计往往呈现出高度雷同的模板化特征：

- **紫蓝渐变与渐变文字：** 无论什么产品，背景必然是暗黑底色加上大面积紫蓝/紫青径向渐变或流光边框。
- **过度玻璃拟态与发光阴影：** `backdrop-blur` 与半透明高亮白边框被无节制滥用，控件悬浮在荧光阴影中。
- **卡片套娃（Card Soup）：** 缺乏文本层级概念，把页面切碎成无数个大圆角矩形，甚至在卡片内部继续套卡片。
- **无脑胶囊按钮（Pill Everywhere）：** 普通管理后台中的保存、提交、筛选等操作全部被做成全圆角胶囊药丸按钮。
- **信息密度极低：** 堆砌大量的 64px+ 无意义空白，关键业务数据需要大范围滚动才能看到。
- **虚假 KPI 与营销横幅：** 在专业生产力软件或运维后台中，突兀塞入巨大的 Hero 横幅和毫无意义的 +12% 伪造指标卡。

### 为什么 AI 会本能产出这种设计？

1. **AI 默认收敛到互联网设计平均值：** 当用户只给出“现代、简洁、高级”等抽象词汇时，大语言模型只能根据海量训练数据采样最高频的流行词汇切片。
2. **AI 本能规避设计风险：** 高密度排版、不对称布局和克制字体层级更容易失败，AI 会倾向选择最不容易出错的通用卡片网格。
3. **严重缺失产品业务上下文：** AI 不了解用户的专业水平、每天使用时长以及高频交互路径，只能把所有页面当做面向消费者的展示型落地页（Landing Page）来设计。
4. **组件库的机械式组合：** 直接使用 Tailwind 或 UI 库的默认尺寸、圆角与间距，导致浓厚的“组件库 Demo”既视感。

## 二、 双引擎治理架构 (Dual-Engine Paradigm)

完整的现代化工程必须同时具备**底层代码工程体系**与 **UI 视觉设计体系**两套平行且互锁的治理流水线：

```text
                    业务需求与产品目标 (Requirement)
                                  ↓
                    产品上下文定义 (PRODUCT_CONTEXT.md)
                                  ↓
          ┌───────────────────────┴───────────────────────┐
          ↓                                               ↓
    代码工程引擎 (Code Engine)                    UI 设计治理引擎 (Design Engine)
   
     AGENTS.md 宪章与规范                           DESIGN_DNA.md 设计人格
          ↓                                               ↓
    ARCHITECTURE.md 整洁架构                        DESIGN.md 视觉规范体系
          ↓                                               ↓
    严格类型与静态 Linter                         design-tokens.json 机器 Token
          ↓                                               ↓
    安全凭证脱敏与反吞噬                          UI_RULES.md 去 AI 味硬约束
          ↓                                               ↓
    单元与回归测试集                              screens/*.md 10种状态规格
          ↓                                               ↓
    编译与构建检测                                无头浏览器多视口实机渲染截图
                                                          ↓
                                                  UI_REVIEW.md 多维视觉审查
          └───────────────────────┬───────────────────────┘
                                  ↓
                    双引擎统一质量门禁 (npm run quality)
                                  ↓
                       全绿 PASS 验证通过
                                  ↓
                     安全合入 Pull Request
```

## 三、 六层去 AI 塑料味工程栈

针对 AI 生成设计的随意性，本项目建立了自顶向下的六层硬约束：

### 第 1 层：产品上下文深度提取 (`PRODUCT_CONTEXT.md`)
明确产品定位、目标用户角色（专业工程师/管理员）、每天使用时长（2-8小时）、核心任务链路以及预期的信息密度（中高密度）。杜绝营销展示思维。

### 第 2 层：设计人格与原型锁定 (`DESIGN_DNA.md`)
选定明确的视觉原型——**临床严谨型 (Clinical Precision)**：
- 结构先于装饰：依靠字阶、字重与 1px 细边框划分空间，坚决不用大面积阴影。
- 克制色彩策略：纯黑石板背景（`#090d16`）、灰度表面（`#0f172a`）、1px 边框（`#334155`）与单点青蓝操作强调色（`#0284c7`）。
- 禁用无意义动效：仅允许 100ms-150ms 的状态微交互，严禁弹跳与果冻动效。

### 第 3 层：负向硬约束守则 (`UI_RULES.md`)
- ❌ 严禁紫蓝/紫青营销渐变背景与渐变文字。
- ❌ 严禁带色荧光投影（`box-shadow: 0 0 20px ...`）。
- ❌ 严禁卡片内部再嵌套卡片（嵌套层级限制为 1）。
- ❌ 严禁标准操作控件使用全圆角胶囊药丸形状。
- ❌ 严禁在控制台与内部工具中放置营销 Hero 宣传条与虚假指标。

### 第 4 层：机器可读设计 Token (`design/design-tokens.json`)
通过 JSON Schema 严格定义空间步进（4, 8, 12, 16, 20, 24, 32px）、圆角梯度（sm: 4px, md: 6px, lg: 8px）以及标准控件高度（sm: 28px, md: 34px, lg: 40px）。严禁在代码中硬编码 `13px`, `17px`, `37px` 等任意数值。

### 第 5 层：页面 10 种关键状态规格 (`design/screens/*.md`)
拒绝只设计“理想静态切图”，所有页面规格与实现必须完整涵盖：
1. **默认态 (Default)：** 正常生产数据展示。
2. **加载中 (Loading)：** 与目标布局等比例的原地骨架屏（无累积布局偏移 CLS）。
3. **空数据 (Empty)：** 单色几何图形、清晰解释与新建主操作。
4. **异常态 (Error)：** 就地红色错误横幅、诊断原因与重试机制。
5. **成功反馈 (Success)：** 瞬态吐司提示与视图数据同步更新。
6. **禁用态 (Disabled)：** 半透明度 (0.45)、禁止点击光标与原因说明。
7. **无权限 (Unauthorized)：** 角色受限提示与申请入口。
8. **离线态 (Offline)：** 本地缓存标记与离线操作队列。
9. **内容溢出 (Overflow)：** 64 字符超长字符串省略号截断与容器抗撑破。
10. **海量数据 (Large Dataset)：** 1,000+ 数据项分页、虚拟滚动与实时过滤。

### 第 6 层：无头浏览器渲染存证与自修复流水线 (`scripts/screenshot.mjs`)
在本地调用无头 Chrome 或 Edge 渲染真实网页，并在桌面（1440x900）、平板（768x1024）与移动端（375x812）抓取截图存入 `screenshots/`。由静态审查脚本与 Agent 共同对照 `UI_REVIEW.md` 逐项检查，发现问题由 Agent 自动定位根因、修改代码并二次渲染，形成完整闭环。

## 四、 核心 CLI 命令参考

```bash
# 1. 运行双引擎统一门禁 (代码格式、类型、架构、安全、Token、UI去塑料味、全套测试)
npm run quality

# 2. 校验设计 Token 与圆角边界规范
npm run ui:tokens

# 3. 静态扫描 UI 代码中的 AI Slop 违规项与页面状态完整度
npm run ui:lint

# 4. 驱动无头浏览器抓取桌面、平板与移动端实机渲染截图
npm run ui:screenshot

# 5. 一键同步 AGENTS.md 宪法至 Cursor、Claude、Gemini、Copilot 与 Windsurf
npm run rule:sync

# 6. 重新编译生成全套中英文高清架构 SVG 矢量图
npm run generate:diagrams

# 7. 运行自动化单元测试与治理回归测试
npm test
```

## 五、 Definition of Done (完成准则) 检查清单

在提交任何 UI 变更或业务代码前，必须确保以下指标 100% 达标：

- [ ] **代码格式：** `npm run format:check` 零格式报错。
- [ ] **静态检查：** `npm run lint` 零警告、零报错。
- [ ] **严格类型：** `npm run typecheck` 严格模式下零类型错误，严禁使用 `any` 降级。
- [ ] **架构边界：** `npm run arch:check` 确保领域层无外层依赖、零循环依赖。
- [ ] **安全规范：** `npm run security:check` 确保零硬编码凭证、零异常静默吞噬。
- [ ] **设计 Token：** `npm run ui:tokens` 验证所有颜色、间距与圆角均对齐 `design-tokens.json`。
- [ ] **去 AI 味审查：** `npm run ui:lint` 确认无紫蓝渐变、无发光边缘、无胶囊按钮泛滥。
- [ ] **多视口实机截图：** `npm run ui:screenshot` 真实生成并验证三端渲染截图。
- [ ] **10 种状态齐全：** 页面规格完整实现 Default、Loading、Empty、Error 等状态。
- [ ] **无障碍合规：** 文本对比度符合 WCAG 2.1 AA (>= 4.5:1)，全键盘交互可见。
- [ ] **全套测试：** `npm test` 保持 100% 通过率。
